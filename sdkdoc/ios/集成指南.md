# iOS 独立 MA SDK 集成指南

本文适用于正式发布的 MTMA 5.5.0。原生独立版 MTMA 5.5.0 要求 iOS 10 及以上，Flutter MA 插件 podspec 已同步声明 iOS 10.0；应用实际最低版本还需满足所用 Flutter 版本的要求。MA 使用自己的 AppKey 独立初始化，AppPush 为可选模块。

本目录提供原生接入参考。Flutter 应用使用 [Flutter API 文档](../../cndocuments/APIs.md) 和 [示例运行说明](../../example/README.md)，由插件完成原生桥接，无需在 AppDelegate 重复初始化 MA。

插件使用 Maven Central / CocoaPods 的正式 5.5.0 依赖，连接生产环境；请配置对应项目的 AppKey。

## 1. 引入正式 SDK

原生工程通过 CocoaPods 引入：

```ruby
pod 'MTMA', '5.5.0'
```

然后执行 `pod install`。Flutter MA 插件的 podspec 已声明该依赖，Flutter 宿主安装 Pods 时会解析它。

仅使用 MA 时无需安装 MTPush，也无需配置 APNs、Push AppKey 或采集广告标识来完成初始化。请使用 CocoaPods 的 MTMA 5.5.0 制品。

## 2. 独立初始化

```objective-c
#import "MTMAService.h"

MTMAConfig *config = [[MTMAConfig alloc] init];
config.appKey = @"YOUR_MA_APP_KEY";

MTMAUserID *identity = [[MTMAUserID alloc] init];
identity.userID = @"your_test_user_id";
config.userID = identity;
config.resultCompletion = ^(MTMAInitResult *result) {
    if (result.isSuccess) {
        NSString *euid = result.EUID;
        NSString *maRid = result.maRID;
        // 初始化成功后执行用户属性、渠道或事件操作。
    } else {
        // 根据 result.code 和 result.message 处理失败。
    }
};
[MTMAService start:config];
```

`appKey` 必须来自 MA 项目，与 Push AppKey 相互独立。正式 SDK 默认使用生产地址；不要添加 QA 地址覆盖。初始化无需等待 MTPush 注册或 APNs Token。

5.5.0 使用 `resultCompletion` 获取结构化结果，包含 `code`、`message`、EUID、MA RID 和成功状态；旧 `completion` 已弃用。通过 `[MTMAService EUID]` 和 `[MTMAService maRID]` 可再次获取标识。

## 3. 可选：接入 AppPush

需要推送时，另外接入 MTPush 并按其指南配置 Push AppKey、Bundle ID、APNs entitlement、证书及通知回调。`channel` 和 `apsForProduction` 属于 Push 配置，不是 MA 初始化参数；APNs 环境应与签名配置一致。

在 MA 控制台的数据来源中启用 AppPush 并选择实际 Push 应用，由 SDK 完成自动绑定。`setChannelValueWithChannelId:values:completion:` 用于第三方 Push 通道，不用于手动设置 AppPush。

Flutter 示例默认仅集成 MA。业务方另行接入 Push 时，需核对 Push 配套版本及依赖约束，并验证服务端自动关联结果。
