# Android 独立 MA SDK 集成指南

本文适用于正式发布的 MA 5.5.0，最低 Android API 23。MA 可以独立初始化，使用 MA 项目的 AppKey；AppPush 为可选模块，Push AppKey 与 MA AppKey 相互独立。

本目录提供原生接入参考。Flutter 应用请使用 [Flutter API 文档](../../cndocuments/APIs.md)，由插件完成原生桥接。

插件使用 Maven Central / CocoaPods 的正式 5.5.0 依赖，连接生产环境；请配置对应项目的 AppKey。

## 1. 引入正式 SDK

在仓库配置中启用 `google()` 和 `mavenCentral()`，应用模块配置：

```groovy
android {
    defaultConfig {
        minSdkVersion 23
    }
}

dependencies {
    implementation 'com.engagelab.plugin:oth_ma:5.5.0'
}
```

仅使用 MA 时，无需引入 `com.engagelab:engagelab`，无需 Push AppKey 占位符、Push Service、Push Receiver 或长连接回调。

## 2. 网络权限

确认最终合并的 AndroidManifest.xml 包含以下权限，原生 MA AAR 已声明它们：

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
```

正式 SDK 默认使用生产地址。请使用生产 MA 项目的 AppKey，不要复制原生测试示例中的 QA 地址或测试 AppKey。MA 接入不要求开启明文 HTTP。

## 3. 独立初始化

在应用的初始化代码中调用，以下示例的 `context` 为应用 Context：

```java
import com.engagelab.privates.push.oth.ma.api.MTMAApi;
import com.engagelab.privates.push.oth.ma.api.MTMAConfig;
import com.engagelab.privates.push.oth.ma.api.MTMAInitResult;
import com.engagelab.privates.push.oth.ma.api.MTMAInitResultCallback;
import com.engagelab.privates.push.oth.ma.api.UserIdentity;

UserIdentity identity = new UserIdentity();
identity.setUserId("your_test_user_id");
MTMAConfig config = new MTMAConfig("YOUR_MA_APP_KEY", identity);
MTMAApi.getInstance(context).start(config, new MTMAInitResultCallback() {
    @Override
    public void onResult(MTMAInitResult result) {
        if (result.isSuccess()) {
            String euid = result.getEuid();
            String maRid = result.getMaRid();
            // 初始化成功后执行用户属性、渠道或事件操作。
        } else {
            // 根据 result.getCode() 和 result.getMessage() 处理失败。
        }
    }
});
```

无需等待 Push 注册或 `onConnectStatus`。初始化结果包含 `code`、`message`、EUID、MA RID 和成功状态；MA RID 与 Push RID 不可混用。

调试时可在初始化前调用 `MTMAApi.configDebugMode(true)`，关闭时传 `false`。默认关闭，该开关独立于 Push 日志。Flutter 对应 `await FlutterPluginEngagelabMa.configDebugMode(true)`，仅支持 Android。

## 4. 可选：接入 AppPush

需要推送时，另外引入 `com.engagelab:engagelab:5.5.0`，按 Push SDK 指南完成应用包名、Push AppKey、组件和通知配置，并初始化 Push。

在 MA 控制台的数据来源中启用 AppPush，选择实际接入的 Push 应用。两个 SDK 分别初始化，原生 SDK 在 Push 身份就绪后自动绑定。不要用 `setChannelValue` 手动绑定 AppPush；该接口用于第三方 Push 通道的 RID 或 Token。

获得两个 RID 只能证明身份已就绪，自动绑定是否成功仍需查询 MA 服务端结果。
